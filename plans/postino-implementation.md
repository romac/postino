# Postino Implementation Plan

Postino is a Scala implementation of the Rust Postcard 1.x binary serialization
format. The first version should prioritize wire compatibility, a small core,
and clear boundaries over broad ecosystem integration.

## Assumptions

- Target wire compatibility is Rust `postcard` 1.x.
- The library is Scala 3-first.
- The build tool is Mill, not sbt.
- The core should be dependency-light and Postcard-specific.
- Scodec integration should be optional, not the foundation.
- Circe should not be part of the initial implementation.
- Verification should use `./mill --no-server ...` commands by default.

## Build Tool Plan

Use an Effed-style Mill setup, but keep it smaller:

- check in a Mill launcher script if the repo does not already have one
- define a Scala 3 module for the Postino core
- use MUnit for tests
- add Scalafmt through Mill for formatting
- keep Rust fixture generation outside the Scala module, under an `interop/`
  or `fixtures/` directory
- add the optional scodec adapter as a separate Mill module only when M4 starts

Initial layout target:

```text
build.mill
mill
src/postino/...
test/src/postino/...
interop/rust-fixtures/...
plans/postino-implementation.md
```

Expected verification commands:

```text
./mill --no-server compile
./mill --no-server test
./mill --no-server fmt
```

If the project becomes multi-module before M4, use explicit module selectors
such as `postino.compile`, `postino.test`, and `postinoScodec.compile`.

## 1. Define The Compatibility Boundary

Success: a short spec note says exactly which Postcard features Postino supports
in v0.

Include:

- primitive types
- varints and zigzag signed integers
- strings and byte arrays
- options
- sequences
- case classes/products
- explicit ADTs/enums

Defer:

- Serde attributes
- schema evolution
- COBS
- CRC
- streaming flavors

## 2. Build The Byte Core

Success: primitive golden tests pass against known Postcard byte examples.

Implement:

- `Reader`
- `Writer`
- `PostinoError`
- unsigned varint decoding with maximum-length and overflow checks
- signed zigzag encoding/decoding
- little-endian `Float` and `Double` encoding

## 3. Define Postino Type Classes

Success: users can call `Postino.encode(value)` and
`Postino.decode[A](bytes)`.

Initial shape:

```scala
trait Encoder[-A]:
  def encode(value: A, out: Writer): Either[PostinoError, Unit]

trait Decoder[+A]:
  def decode(in: Reader): Either[PostinoError, A]

trait Codec[A] extends Encoder[A] with Decoder[A]
```

Keep this independent from Circe and scodec.

## 4. Add Primitive Codecs

Success: each primitive matches Rust Postcard output.

Cover:

- `Boolean`
- `Byte`
- `Short`
- `Int`
- `Long`
- `Float`
- `Double`
- `String`
- `Array[Byte]`
- unsigned wrappers such as `U16`, `U32`, and `U64`

## 5. Add Collection Codecs

Success: variable-length values use `varint(usize)` length prefixes.

Cover:

- `Option[A]`
- `List[A]`
- `Vector[A]`
- generic arrays where practical
- a special fast path for `Array[Byte]`

## 6. Add Product Derivation

Success: case class fields encode in constructor order with no field names and
no length prefix.

Use Scala 3 `Mirror.ProductOf[A]`.

Example target:

```scala
case class Sensor(id: U16, temp: Int, label: String) derives Codec
```

## 7. Add Explicit Sum/Enum Support

Success: sealed traits require explicit discriminants.

Do not silently derive variant order from compiler subtype order. Rust interop
requires enum variant numbers to be part of the schema.

Example API:

```scala
given Codec[Message] =
  Postino.sum[Message]
    .variant(0, Codec[Ping])
    .variant(1, Codec[Pong])
    .variant(2, Codec[Data])
    .build
```

## 8. Create Rust Golden Tests

Success: Scala encodes match Rust `postcard::to_stdvec`, and Scala decodes
Rust-generated bytes.

Use a small Rust fixture generator with representative schemas:

- primitives
- nested case classes
- options
- lists
- byte arrays
- enums

## 9. Add Optional Scodec Module

Success: existing scodec users can adapt Postino codecs.

Module:

```text
postino-scodec
```

API:

```scala
def toScodec[A](using Postino.Codec[A]): scodec.Codec[A]
```

This keeps scodec integration useful without letting scodec dictate Postino's
model.

## 10. Defer Circe

Success: no Circe dependency in v0.

Circe can wait until there is a concrete use case, likely debugging or schema
tooling, not wire encoding.

## Milestones

These are historical implementation milestones. Their numbers do not correspond to the Maven prerelease suffixes. The `0.1.0-M1` release already included implementation milestones M0 through M5.

### M0: Mill Project Skeleton

- add `mill` launcher and `build.mill`
- configure a Scala 3 core module
- configure MUnit tests
- configure Scalafmt
- verify with `./mill --no-server compile`, `./mill --no-server test`, and
  `./mill --no-server fmt`

### M1: Byte Core And Primitive Compatibility

- byte reader/writer
- varints
- zigzag signed integers
- primitive codecs
- primitive Rust golden tests

### M2: Collections And Products

- options
- sequences
- byte arrays
- case class derivation

### M3: Explicit Enums And Interop Coverage

- explicit enum builder
- nested Rust fixtures
- enum Rust fixtures

### M4: Scodec Adapter

- `postino-scodec` module
- adapter from `Postino.Codec[A]` to `scodec.Codec[A]`

### M5: Documentation And Publishing

Status: complete as of 2026-05-19.

- README examples
- compatibility note
- unsupported-feature list
- publish setup through Mill `publishLocal`, `publishM2Local`, and
  `publishSonatypeCentral` tasks for the core and scodec modules
